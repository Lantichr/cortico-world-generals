# Tools and event contracts

Tool descriptions and parameter schemas are declared by `GeneralsWorld.tools()`. Names begin with `generals_`; event types begin with `generals.`. The host exposes these tools to its Persona. The [operations guide](operations.md) covers setup, and the [architecture guide](architecture.md) describes S1 policy assumptions.

| Purpose | Tools |
| --- | --- |
| Current connection and map | `generals_observe`, `generals_view_map` |
| Selected facts and visible forces | `generals_inspect_tiles`, `generals_list_armies` |
| Read-only route calculations | `generals_check_moves`, `generals_simulate_moves`, `generals_plan_gather` |
| Manual movement | `generals_attack`, `generals_move_path`, `generals_queue_moves`, `generals_clear_moves` |
| Autonomous delegation and reports | `generals_start_agent`, `generals_stop_agent`, `generals_agent_status`, `generals_strategy_brief` |
| Structured strategy | `generals_set_intent`, `generals_clear_intent` |
| Room and account | `generals_join_private`, `generals_set_force_start`, `generals_leave`, `generals_set_username` |

## Connection and admission

`generals.connection` includes current `status`, `phase` and `room`. A fresh connection has `phase=connected` and `room=null`; restarting does not restore a room or force-start vote. Retained lobby events describe their earlier connection. Use `generals_observe` to check current room, phase and lobby before announcing admission or readiness for another game.

Admission is confirmed by a server `queue_update`, which changes `join-requested` to `lobby`. `generals_observe` includes the latest lobby snapshot and `lastError`. `gio_error` is delivered as `generals.error`; when received during admission it clears the requested room so a corrected request can be sent. An empty `error_set_username` reply is delivered as `generals.account` and confirms registration; nonempty replies are errors. If the server requires a username, register it for the configured account before retrying. Another socket using the same account can replace its lobby seat; stop the World before running an account probe.

## Observations and history

`snapshotIntervalMs` limits map-event creation, while observation reads every received update. Automatic play archives full map events without delivering them into model context; manual play delivers deferred maps rendered from the latest server view. Superseded snapshots are dropped. Full observation remains available on demand in either mode. The World retains server fog markers and caches dated facts from visible tiles within one game. It does not infer hidden updates. Movement receipts confirm transmission only. Malformed map or transport packets end the connection; restart to obtain a fresh full map.

Map decoding accepts armies and terrain blocks with an optional third tunnel-limit block. Each snapshot array contains exactly `width * height` entries. `tunnelLimits` contains zero when absent, a positive incoming army limit when visible, or -1 when the tunnel limit is hidden.

`generals_view_map` and `generals_observe` with `format=compact` return a coordinate grid. `generals.state` events use the same compact view, identified by `format=compact`; older stored events can contain raw arrays. `generals_observe` defaults to `format=raw`. Grid cells contain owner and army (`p0:12`), neutral army (`.:3`), mountain (`#`), fog (`?`) or an obstacle in fog (`X`). Visible cells carry general (`G`), city (`C`) and tunnel-limit (`T20`, or `T?` when unknown) suffixes.

Previously seen fog cells retain their current `?` or `X` prefix and add `~` followed by historical terrain or features: `?~.` for ordinary land, `X~#` for a mountain, `?~G` for a general, and `X~CT` for a city with a tunnel. The grid includes no historical army or owner. Historical features can be stale, including a general captured since it was seen. Never-seen tiles retain plain `?` or `X`; raw arrays retain the server view.

Raw and compact views include `enemyGenerals`, also delivered in `generals.state` events. It lists players other than self and confirmed allies: `p0 G?` before a sighting, or `p0 G(12,5) 422@2362 last` for the last verified position, army and server turn. `seen` marks a sighting in the current turn; `last` preserves historical facts without estimating hidden armies or assuming the general remains there. `p0?` marks an unknown team relation. Each player's record updates only from a currently visible general owned by that player, and resets with the game view or changed dimensions.

`playerLifecycle` records each player's `status`, `basis`, `observedTurn` and last confirmed `generalIndex`. A score's `dead=true` makes the player `inactive`; remaining visible garrisons and a known capturable general stay available. Zero remaining tiles together with `dead=true`, or a visible known general now owned by another player or neutral without an explicitly active score, establish `eliminated`. `basis=captured` or `neutralized` requires observing that ownership change; a zero-tile score alone uses `unknown`. An explicit `dead=false` preserves `active`: if the former general changed owner, its coordinate is discarded until a new general position arrives. A missing general coordinate or marker does not establish elimination. Elimination stays recorded through fog unless a later explicit active score corrects it or the game view resets. Inactive records append `inactive` to `enemyGenerals`; eliminated records replace the old location with `eliminated:<basis>`. Historical tile facts remain dated and are not erased. S1 excludes inactive and eliminated players from moving-threat estimates. Without evidence of inactivity, `active` with `basis=unknown` keeps possible movement under consideration.

Raw and compact views and `generals.state` events include `generalEnemyNeighbors` when the currently confirmed self general has visible enemy or relation-unknown neighbors among its eight surrounding tiles. Entries such as `p0(3,8):1; p3?(5,8):0` give owner, coordinates and current armies in row-major order; `?` marks an unknown relation. Selection uses ownership without an army threshold and excludes self, confirmed allies, neutral tiles, mountains and fog history. The field is omitted when no tiles qualify or the self general is not currently confirmed. It reports neighboring ownership, not the opponent's actual vision or knowledge. Environment guidance uses it to locate nearby scouts, verify tiles and reclaim enemy territory while preserving general defense.

`generals_inspect_tiles` accepts a nonempty `tiles` array of indices or `{x,y}` coordinates. It returns `observedTurn` and each tile's `current` facts with `visible`, plus `lastSeen` facts with `lastSeenTurn`. A never-seen tile has `lastSeen=null`; hidden current armies, ownership and features are null. Only visible updates replace cached facts. Inspection sends no moves and does not refresh hidden information. History resets on a new game, cleared view, disconnect or changed map dimensions. Movement validation uses current terrain.

`generals_list_armies` locates the largest currently visible owned stacks without returning a full map or sending moves. `side` defaults to `self`, accepts `enemy` for confirmed opponents, and `all` for separate `self`, `enemy`, `allies` and `unknown` rankings. Missing team relations are not classified as enemies. `limit` defaults to 10 and accepts 1–20 per group. Receipts include `playerIndex`, `observedTurn`, `side`, `limit` and `groups`; each tile has `x`, `y`, `owner`, `armies`, `general` and `city`. Rankings use descending army count with row-major tile order for ties. Neutral, nonpositive-army and hidden tiles are excluded; last-seen armies are never ranked. General garrisons can appear, so rank does not establish safe troop availability or route feasibility. Rankings are queried on demand and are not added to map events.

Raw and compact views include `selfScore`, selected by `playerIndex`, and `selfGeneral` with the observed general garrison. Raw observation retains `selfTiles`, coordinates, features and player metadata arrays. Compact views omit these repeated arrays and render one space between grid cells. `playerLegend` maps stable player indices to the default Bot Server palette through `playerColors`, with self, teammate or enemy relations from `teams`. Missing color or team metadata is marked unknown; browser color themes may differ. Observation, map events and movement receipts include `moveProgress`: the last locally sent attack index, the most recent server-reported attack index and its observed turn, and the last clear request. Missing server indices remain null; an update without an index preserves the prior index and its turn. A reported processing index does not establish a successful move. Clear requests record transmission only; the World does not infer remaining queue length or clear acknowledgement. These facts reset on a new game or when the current view is cleared.

## Movement and filtering

`generals_attack` appends one supplied adjacent move using `from`, `to` and optional `half` (default `false`). Full movement leaves one army; half movement uses the army count at execution. The tool does not choose a source or destination.

`generals_queue_moves` appends ordered `{from,to,half}` moves. `generals_move_path` appends consecutive edges of a supplied path; `half` is either a boolean for all edges or one boolean per edge. Both accept tile indices and `{x,y}` coordinates. The entire request is validated before any move is sent, including map bounds and edge adjacency. Ownership and combat legality remain server decisions, allowing later moves to start from tiles acquired earlier in the queue. All movement tools share increasing attack indices and append to the same server queue; they do not find paths or choose targets. Clear remaining moves with `generals_clear_moves` before replacing a route.

Movement filtering skips steps whose current source or target terrain is a known mountain (-2), and sends the others in their original order. `skipped` reports every removed step with `reason=known_mountain`, `mountainEndpoints` and endpoint facts. `moves`, `checks` and `skipped` retain original one-based `step` numbers; only sent moves consume attack indices. If every step is skipped, `sent=null` and move progress is unchanged; single attacks also return `check=null`. Filtering does not replan or remove dependent later edges, so a path can become disconnected. Malformed arguments, out-of-bounds coordinates and nonadjacent edges still reject the whole request before sending. Coordinate objects accept only `x` and `y`. Fog obstacles and historical mountain features are not filtered as current mountains.

Movement receipts and `generals_check_moves` include `filteredRoutes` for original chains affected by filtering. A chain continues only when the previous target equals the next source; independent moves start separate chains. Each entry gives the original `firstStep`/`lastStep` range and `retainedSegments`, consecutive retained edge ranges with their endpoint coordinates. Unfiltered chains are omitted; a fully filtered chain has no retained segments. These ranges describe missing submitted edges, not execution or available troops. A later segment can still use troops already at its source or arriving through other queued moves.

`generals_check_moves` previews the same filtering without sending, returning retained `checks` and `skipped`. Inspection and movement receipts include `playerIndex` to identify the local player alongside current coordinates, terrain, ownership and armies. Unknown armies and features are null; future ownership and combat outcomes are not simulated.

## Read-only calculations

`generals_simulate_moves` calculates up to 100 ordered moves on a copy of the latest map. It accounts for full/half rounding, source garrisons, merging, combat and turn production. Each step reports the pre-action `turn` and post-combat, pre-production armies; `touchedTiles` reports the simulation's final values. It stops at the first unknown tile, mountain, non-owned or unusable source, tunnel or allied transfer, retaining the completed prefix. General capture records the local result and stops before modeling the defeated player's other territory. Historical fog armies and one-army zero-troop transfers are outside its model. It sends no packets or changes to observation, history or attack indices.

`generals_plan_gather` accepts a currently visible self-owned `target` and a shared `maxMoves` budget of 1–100. Optional `targetArmies` includes the target's original garrison and production through `deadlineTurn=observedTurn+maxMoves`. `sources` limits candidate starts; intermediate owned troops still merge. `reserves` contains `{tile,armies}` minimum departure garrisons; by default the self general retains its current garrison, and an explicit entry overrides that value. The greedy `method=greedy_owned_routes` selects shortest visible self-owned routes without tunnels by added target armies per action, updating the simulated board after each accepted route. Reserve-constrained departures use half moves if they retain enough armies. It does not search waiting before departure or alternate paths; an unmet amount does not prove infeasibility. `skipped` summarizes final-round exclusions with at most ten examples.

S1's gathering tree does not change this read-only tool's `greedy_owned_routes` algorithm.

Gather results include coordinate `moves` suitable for `generals_queue_moves`, `usedMoves`, `actionEndTurn`, action-end `projectedArmies`, deadline `armyAtDeadline`, and `metTarget` (null when no amount was requested). Unused budget turns count as idle production; an empty move list needs no submission. Both calculation tools assume immediate serial execution from `observedTurn`, no existing queue, and no other player moves. They support standard rules and City-State, and reject known other modifiers, custom maps, deserts, swamps, chess clocks or neutral-city regeneration. Missing room metadata assumes standard rules. Predictions do not account for model latency or guarantee defense; inspect current facts and `moveProgress` before deciding to clear, recalculate or send. Calculation results are returned on demand, without adding map-event context.

## Control and strategic intents

The default control mode is `manual`. Autonomous delegation works on unmodified Cortico 0.2.3; [host pause integration](host-compatibility.md) is optional.

`generals_agent_status`, `generals_observe.agent` and `generals_strategy_brief` include `operatorPauseLinked`, which becomes true after the host forwards a pause notification. `operatorPaused=false` only says this World is not currently blocking actions; it does not establish integration. Without integration, global pause leaves S1 running. With integration, pause stops new movement and autonomous start votes, invalidates the decision and intent, and requests queue clearing; resume retains delegation with a new control epoch. Use `generals_stop_agent` to revoke delegation and request queue clearing, or deactivate the World to stop its local engine. The remote game continues, and processed moves cannot be recalled.

`generals_start_agent` explicitly delegates one game to S1, a rule-and-search agent that chooses expansion, exploration, city capture, gathering, defense, interception and general attacks without model calls. It supports confirmed standard or City-State 1v1 or free-for-all games; known unsupported rules, allied transfers and tunnels stop autonomous control with an error. This heuristic policy does not guarantee victory. S2 supplies optional strategic intents through World tools; S1 continues autonomous play without an intent or a model reply. `agent/contracts.ts` separates observations, decisions, actions, feedback and strategic intents.

`generals_start_agent({room,forceStart})` joins the supplied room if unseated, or uses the current room. `forceStart` defaults to false; true sends one start vote after confirmed lobby admission. Delegation does not register an account username. A result ends autonomous control, and the next game requires leaving and a new delegation. `generals_stop_agent` restores manual control and requests clearing remaining server moves. While S1 owns movement, manual attack, route, batch and queue-clear tools reject requests; read tools remain available. Both control modes use one `MoveExecutor` and attack-index sequence.

`generals_strategy_brief` returns current `gameId`, `controlEpoch`, `turn`, `playerIndex` and `intent.lastRevision`. S2 submits a complete `StrategyIntent` with `generals_set_intent`: `revision` must increase within the current game and control epoch, `basedOnTurn` must not be in the future, and `expiresTurn` is an exclusive upper bound. Goals are `auto`, `expand`, coordinate-targeted `capture_city`, `gather`, `defend`, `scout`, or `attack_general` with an opponent player index. Gathering and defense targets must be currently owned; city targets must be known cities. Invalid or stale submissions preserve the accepted intent and record `lastRejection`. Accepted changes affect subsequent decisions and cannot recall already sent actions.

`constraints.reserves` sets minimum departure garrisons on currently owned tiles; it does not request immediate reinforcement. `constraints.avoidTiles` excludes route tiles, including sources. These hard constraints apply to complete candidate routes, gathering trees and send-time checks, including emergency defense. Goals and optional `preferences` influence candidate ranking within legality and timing checks. Emergency tactics may preempt a goal. `following`, `preempted`, `blocked` and `completed` report policy outcomes; a blocked search does not prove infeasibility. Once city capture, scouting or a general attack is observed complete, that revision stays complete and retains its constraints until replacement, clearing or expiry. Other goals remain active until cleared, invalidated or expired.

An `attack_general` intent completes when the target player's lifecycle is `eliminated`. An inactive player with a known general remains a valid attack target; an unknown location blocks the goal. Strategy briefs include `facts.players` with each player's `status` and `basis`, preserve visible inactive garrisons in `enemyForces`, and omit eliminated general targets. Lifecycle changes trigger an earlier strategy report.

An active `gather` intent retains the target garrison after troops arrive. Ordinary expansion, scouting, city capture and transport cannot withdraw from that tile, including transit through it in a longer plan; other forces remain available for autonomous tasks. Defense, interception and an adjacent general capture may preempt gathering within the existing hard constraints and timing checks. Replace the intent to deploy the gathered army for an offensive task. Clearing, expiry or invalidation releases the gathering target.

Every accepted intent replaces the previous intent, including all constraints. `generals_clear_intent({gameId,controlEpoch,revision})` uses the same increasing revision ledger and removes the goal and constraints while S1 continues playing. Neither tool clears server moves or sends an extra action in the current turn. Start, stop, set-intent and clear-intent tools require reading their receipts before subsequent tools. Read tools remain available during autonomous play; direct movement and queue clearing require explicit manual takeover with `generals_stop_agent`. In-game chat has no authority to submit intents.

An intent uses this structure. Replace every game, epoch, revision, turn and target value with current observed values before submitting it:

```json
{"gameId":"current-game","controlEpoch":4,"revision":3,"basedOnTurn":100,"expiresTurn":160,"goal":{"kind":"capture_city","target":{"x":10,"y":6}},"constraints":{},"preferences":{"emphasis":"economy","risk":"normal"}}
```

`preferences` is optional; when provided, it contains both `emphasis` (`balanced`, `economy`, `pressure`, `information`) and `risk` (`low`, `normal`, `high`). Higher risk does not bypass legal or timing checks. `rationale` records an explanation and executes no natural-language commands. `expired`, `cancelled`, `invalidated` and `stopped` report expiry, clearing, invalid facts/control versions and stopped control. Read `generals_agent_status` for the complete active intent before replacing it; the brief includes only constraint counts.

## Action feedback and AFK

Feedback `server_processed` means the server index reached the action, `map_changed` means observed endpoints changed without that confirmation, `unconfirmed_timeout` means processing was not confirmed within three observed turns, and `cancel_requested` means a clear request was sent. Endpoint changes can include production or another player's action; none of these labels alone proves successful movement or capture. Unconfirmed actions trigger a clear request before further replanning.

`generals.afk` forwards raw `afk_warning` events and transitions of the local player's score `warn_afk` flag before map throttling. Observation includes that flag, the latest warning and the last sent move's timestamp, attack index and observed turn. Sending a move does not establish that the server executed it or reset an AFK check. The World does not infer an AFK deadline; automatic play requires explicit S1 delegation.
